## Background

In this sample project, we use Specmatic to contract test a React frontend that consumes the Order BFF over REST/OpenAPI. Specmatic reads the BFF OpenAPI contract and starts a mock BFF API so the frontend workflows can be tested without a real backend. The [Order BFF OpenAPI spec](https://github.com/specmatic/specmatic-order-contracts/blob/main/io/specmatic/examples/store/openapi/product_search_bff_v6.yaml) is used for stubbing the BFF dependency consumed by this frontend.

## Why Specmatic

* **Auto-generated tests from your API spec** - Specmatic reads your OpenAPI spec and generates realistic mock behavior from the contract.
* **Intelligent service virtualisation** - the frontend can develop and test against a BFF mock without waiting for the real BFF.
* **Backward compatibility detection** - the same spec can be checked for breaking changes before frontend workflows drift.
* **Works with your existing OpenAPI spec** - no new DSL is needed for REST contracts.

## Run Contract Tests

### Prerequisites

* Node.js 20.x
* Docker Desktop or a compatible Docker engine
* `SPECMATIC_LICENSE_KEY` for the Enterprise runtime image `specmatic/enterprise:1.19.1`

The Specmatic configuration lives in [`specmatic.yaml`](specmatic.yaml). First run may take 1-2 minutes as Specmatic clones the configured contract repository. Subsequent runs are fast because contracts are cached in `.specmatic/`.

### Using the build tool

For **Unix based systems** and **Windows PowerShell**:

```shell
npm ci
npm test
```

For **Windows Command Prompt**:

```bat
npm ci
npm test
```

### Using Docker

The contract tests use Testcontainers, so Docker is started by the test suite:

```shell
docker pull specmatic/enterprise:1.19.1
npm test
```

#### View Specmatic Test Reports

After running the contract tests, you can view the HTML report generated by Specmatic in [build/reports/specmatic/stub/html](build/reports/specmatic/stub/html/). The CTRF output is generated in [build/reports/specmatic/stub/ctrf](build/reports/specmatic/stub/ctrf/).

### Test Modes

This sample ships with `schemaResiliencyTests: all` in `specmatic.yaml`. Because this is a frontend consumer sample, Specmatic runs in mock mode and the React/Vitest suite determines which workflows are exercised.

| Mode | What it does |
|------|-------------|
| `none` | Runs tests from named examples only when Specmatic is in test mode |
| `positiveOnly` | Adds all valid input combinations in test mode |
| `all` | Adds negative/boundary tests in test mode |

To change, update `specmatic.yaml`:

```yaml
specmatic:
  settings:
    test:
      schemaResiliencyTests: none
```

## How It Works

BFF Spec -> specmatic.yaml -> Specmatic mocks the BFF API -> Your frontend calls the mock -> Contract compliance verified.

When you run `npm test`, Vitest starts a Testcontainers-managed `specmatic/enterprise:1.19.1` container. Specmatic reads `specmatic.yaml`, fetches the BFF contract, starts the mock API, and the React client tests execute product and order workflows against that mock.

## Configuration

| Environment Variable | Default | Description |
|---------------------|---------|-------------|
| `VITE_BFF_BASE_URL` | `http://localhost:8090` | BFF base URL used by the React app |
| `STUB_BASE_URL` | `http://localhost:8090` | Base URL used by Specmatic for the BFF mock |
| `SPECMATIC_REPORT_DIR` | `build/reports/specmatic` | Root directory for Specmatic HTML and CTRF report output |
| `FRONTEND_PORT` | `3000` | Vite dev server port |

## Project Structure

| File | Purpose |
|------|---------|
| `specmatic.yaml` | Contract mock configuration pointing to the BFF OpenAPI spec |
| `src/api.ts` | Typed BFF client for product, order, and monitor operations |
| `src/App.tsx` | React workflows that call the BFF client |
| `test/bffClient.contract.test.ts` | Contract consumption tests against the Specmatic mock |
| `test/specmaticMock.ts` | Testcontainers adapter for `specmatic/enterprise:1.19.1` |
| `Dockerfile` | Production container image for the built React app |
| `.github/workflows/ci.yml` | CI pipeline: test, report upload, and Docker build |
