## Background

In this sample project, we use Specmatic to contract test a FastAPI backend over REST/OpenAPI. Specmatic reads the API contract and auto-generates requests against the running service, so the provider behavior is checked against the same specification that consumers use. [Order API's OpenAPI spec](https://github.com/specmatic/specmatic-order-contracts/blob/main/io/specmatic/examples/store/openapi/api_order_v5.yaml) is used for running contract tests against this API. This backend keeps product and order state in memory and uses an in-memory inventory boundary, so no external dependency process is required.

## Why Specmatic

* **Auto-generated tests from your API spec** - Specmatic reads your OpenAPI spec and generates test cases automatically. No hand-written contract test cases to maintain.
* **Intelligent service virtualisation** - the same configuration model can stub dependencies from their contracts, letting teams develop in parallel.
* **Backward compatibility detection** - Specmatic can compare spec versions and flag breaking changes before they reach production.
* **Works with your existing OpenAPI spec** - no new DSL is needed for REST APIs.

## Run Contract Tests

### Prerequisites

Install Python 3.12 and JRE 17+. Set `SPECMATIC_LICENSE_KEY` for Specmatic Enterprise. The test script downloads `io.specmatic.enterprise:executable-all:1.19.1` from Maven Central into `tools/` on first run.

For **Unix based systems** and **Windows PowerShell**:

```shell
pip install -r requirements.txt
pytest test -v -s
```

For **Windows Command Prompt**:

```bat
pip install -r requirements.txt
pytest test -v -s
```

First run may take 1-2 minutes as Specmatic clones the configured contract repository. Subsequent runs are fast because contracts are cached in `.specmatic/`.

[specmatic.yaml](specmatic.yaml) configures the contract source, the service under test, report generation, and schema resiliency mode.

#### View Specmatic Test Reports

After running the contract tests, you can view the HTML report generated by Specmatic in [build/reports/specmatic](build/reports/specmatic/). The same directory also contains the CTRF output for CI tooling.

### Test Modes

This sample ships with `schemaResiliencyTests: all` which runs the full test suite including negative/boundary tests. You can adjust the mode in `specmatic.yaml`:

| Mode | What it does |
|------|-------------|
| `none` | Runs tests from named examples only (fastest) |
| `positiveOnly` | Adds all valid input combinations |
| `all` | Adds negative/boundary tests and expects contract-declared 4xx responses |

To change, update `specmatic.yaml`:

```yaml
specmatic:
  settings:
    test:
      schemaResiliencyTests: none
```

## How It Works

API Spec -> specmatic.yaml -> Specmatic generates requests -> FastAPI responds -> Specmatic validates responses against the spec.

When you run the test command, the Python test starts the FastAPI app, invokes the Specmatic Enterprise CLI with `java -jar`, and streams the contract test output. Specmatic reads `specmatic.yaml`, fetches the contract from GitHub, generates test cases, and validates status codes, content types, and response bodies.

## Configuration

| Environment Variable | Default | Description |
|---------------------|---------|-------------|
| `SUT_PORT` | `8080` | FastAPI application port |
| `SUT_BASE_URL` | `http://localhost:8080` | Base URL used by Specmatic tests |
| `SPECMATIC_LICENSE_KEY` | none | Enterprise license key used by Specmatic |

## Project Structure

| File | Purpose |
|------|---------|
| `specmatic.yaml` | Contract test configuration pointing to the Order API spec |
| `src/order_api/app.py` | FastAPI routes implementing the contract operations |
| `src/order_api/store.py` | In-memory product, order, and inventory state |
| `scripts/run_contract_tests.py` | Starts the app and runs the Specmatic Enterprise CLI |
| `test/test_contract.py` | Test entrypoint for the local Python command |
| `Dockerfile` | Production container image |
| `.github/workflows/ci.yml` | CI pipeline for tests, reports, and Docker build |
