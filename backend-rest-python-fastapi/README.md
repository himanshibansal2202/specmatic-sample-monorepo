## Background

In this sample project, we use Specmatic to contract test a FastAPI backend for the Order API over REST/OpenAPI. Specmatic reads the API specification and auto-generates requests against the running service, so the backend is verified against the contract rather than hand-written assertions. The backend owns in-memory Products and Orders state and does not require external service dependencies.

* [Order API OpenAPI spec](https://github.com/specmatic/specmatic-order-contracts/blob/main/io/specmatic/examples/store/openapi/api_order_v5.yaml) is used for running contract tests against this API.

## Why Specmatic

* **Auto-generated tests from your API spec** - Specmatic reads the OpenAPI spec and generates contract test cases automatically.
* **Works with your existing OpenAPI spec** - no new DSL is needed for REST contract tests.
* **Backward compatibility detection** - Specmatic can compare spec versions and flag breaking changes before they reach production.
* **Single source of truth** - the same spec drives contract tests, service virtualisation, and compatibility checks.

## Tech

1. Python 3.14.6 service written with FastAPI 0.137.1
2. Specmatic Enterprise `io.specmatic.enterprise:executable-all:1.18.0`
3. JRE 17+ for running the Specmatic Enterprise CLI JAR
4. Pytest test adapter that starts the app and invokes `java -jar` directly

## Run Contract Tests

### Prerequisites

* Python 3.14.6
* JRE 17+
* `SPECMATIC_LICENSE_KEY` configured for Specmatic Enterprise
* Network access to Maven Central and the contract repository on first run

First run takes 1-2 minutes as Specmatic downloads the Enterprise runtime and clones the contract repository. Subsequent runs are fast because `.specmatic/` and `.specmatic-runtime/` are cached locally.

The [specmatic.yaml](specmatic.yaml) file configures the contract repository, spec path, test endpoint, coverage governance, and schema resiliency mode.

### Using the build tool

For **Unix based systems** and **Windows PowerShell**:

```shell
pip install -r requirements.txt
pytest test -v -s
```

For **Windows Command Prompt**:

```bat
pip install -r requirements.txt
pytest test -v -s
```

#### View Specmatic Test Reports

After running the contract tests, you can view the HTML report generated by Specmatic in the following location:
[build/reports/specmatic/test/html/index.html](build/reports/specmatic/test/html/index.html)

### Test Modes

This sample ships with `schemaResiliencyTests: all` which runs the full test suite including negative and boundary tests. You can adjust the mode in `specmatic.yaml`:

| Mode | What it does |
|------|-------------|
| `none` | Runs tests from named examples only (fastest) |
| `positiveOnly` | Adds all valid input combinations |
| `all` | Adds negative and boundary tests; expects 400 for invalid inputs (default) |

To change, update `specmatic.yaml`:

```yaml
specmatic:
  settings:
    test:
      schemaResiliencyTests: none
```

## How It Works

```text
API Spec (OpenAPI) -> specmatic.yaml -> Specmatic generates requests -> FastAPI responds -> Specmatic validates responses against the spec
```

When you run the test command, pytest starts the FastAPI service on an available port, sets `SUT_BASE_URL` for Specmatic, and invokes the Specmatic Enterprise CLI with `java -jar`. Specmatic reads `specmatic.yaml`, fetches `api_order_v5.yaml`, generates contract tests, and validates every response status, content type, and body shape.

## Configuration

| Environment Variable | Default | Description |
|---------------------|---------|-------------|
| SUT_HOST | 127.0.0.1 in tests, 0.0.0.0 for `scripts/run_app.py` | Application bind host |
| SUT_PORT | 8080 for app runs, random free port in tests | Application port |
| SUT_BASE_URL | http://localhost:8080 | Base URL used by Specmatic tests |
| SUT_ACTUATOR_URL | http://localhost:8080/openapi.json | OpenAPI endpoint used for coverage discovery |
| SPECMATIC_ENTERPRISE_JAR | unset | Optional local path to the Enterprise executable JAR |
| SPECMATIC_LICENSE_KEY | unset | Specmatic Enterprise license key |

## Project Structure

| File | Purpose |
|------|---------|
| `specmatic.yaml` | Contract test configuration pointing to the Order API spec |
| `src/app/main.py` | FastAPI routes, in-memory store, validation, and error responses |
| `test/test_contract.py` | Contract test adapter that starts the app and runs Specmatic Enterprise CLI |
| `scripts/run_app.py` | Local application runner |
| `Dockerfile` | Production container image |
| `.github/workflows/ci.yml` | CI pipeline for contract tests and Docker build |
| `.specmatic-sample-manifest.json` | Generated sample metadata and verification results |
