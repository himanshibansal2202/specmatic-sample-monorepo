## Background

In this backend sample project, Specmatic contract-tests a TypeScript Express implementation of the Order API over REST/OpenAPI. Specmatic reads the executable OpenAPI contract and auto-generates provider tests against the running service; no real downstream services are required because the inventory boundary is implemented in memory for the sample.

* [Order API v5 OpenAPI spec](https://github.com/specmatic/specmatic-order-contracts/blob/main/io/specmatic/examples/store/openapi/api_order_v5.yaml) is used for running contract tests against the API.

## Why Specmatic

* **Auto-generated tests from your API spec** - Specmatic reads the OpenAPI spec and generates provider test cases automatically.
* **Works with your existing OpenAPI spec** - no new DSL is needed for this REST contract.
* **Backward compatibility detection** - Specmatic can compare spec versions and flag breaking changes before release.
* **Single source of truth** - one spec drives contract tests, stubs, and compatibility checks.

## Run Contract Tests

### Prerequisites

Install Node.js 18+, npm, and Docker. The contract test uses the official Specmatic Enterprise runtime `specmatic/enterprise:1.19.1`, so set `SPECMATIC_LICENSE_KEY` in your environment.

First run may take 1-2 minutes as Specmatic clones the configured contract repository. Subsequent runs are fast because contracts are cached in `.specmatic/`.

### Using the build tool

For **Unix based systems**:

```shell
npm install
npm test
```

For **Windows PowerShell**:

```shell
npm install
npm test
```

For **Windows Command Prompt**:

```shell
npm install
npm test
```

The [specmatic.yaml](specmatic.yaml) file configures the contract source, tested spec, test base URL, report formats, and schema resiliency mode.

#### View Specmatic Test Reports

After running the contract tests, you can view the HTML report generated by Specmatic in [build/reports/specmatic](build/reports/specmatic/). The same directory also contains the CTRF output for CI tooling.

### Test Modes

This sample ships with `schemaResiliencyTests: all` which runs the full test suite including negative/boundary tests. You can adjust the mode in `specmatic.yaml`:

| Mode | What it does |
|------|-------------|
| `none` | Runs tests from named examples only (fastest) |
| `positiveOnly` | Adds all valid input combinations |
| `all` | Adds negative/boundary tests and expects contract-declared error responses for invalid inputs (default) |

To change, update `specmatic.yaml`:

```yaml
specmatic:
  settings:
    test:
      schemaResiliencyTests: none
```

## How It Works

OpenAPI spec -> `specmatic.yaml` -> Specmatic generates requests -> Express service responds -> Specmatic validates responses against the spec.

When you run `npm test`, the test adapter starts the Express app on `SUT_PORT`, exposes that host port to Docker, and starts `specmatic/enterprise:1.19.1` through Testcontainers. Specmatic reads `specmatic.yaml`, fetches the contract from GitHub, generates test cases, and validates the service response status, content type, and body shape.

## Configuration

| Environment Variable | Default | Description |
|---------------------|---------|-------------|
| `SUT_PORT` | `8080` | Application port |
| `SUT_BASE_URL` | `http://localhost:8080` | Base URL used by Specmatic when not overridden by the test adapter |
| `SCHEMA_RESILIENCY_TESTS` | `all` | Specmatic test generation mode |
| `SPECMATIC_MIN_COVERAGE` | `68` | Minimum API coverage threshold for the final run |
| `SPECMATIC_MAX_MISSED_OPERATIONS` | `0` | Maximum missed operations allowed for the final run |
| `SPECMATIC_COVERAGE_ENFORCE` | `true` | Whether Specmatic enforces API coverage governance |
| `SPECMATIC_LICENSE_KEY` | empty | Enterprise license key used by the Specmatic Docker image |

## Project Structure

| File | Purpose |
|------|---------|
| `specmatic.yaml` | Contract test configuration pointing to the Order API spec |
| `src/app.ts` | Express routes implementing products and orders |
| `src/store.ts` | In-memory product, order, and inventory state |
| `test/contract.test.ts` | Testcontainers adapter that starts the app and runs Specmatic Enterprise |
| `Dockerfile` | Production container image |
| `.github/workflows/ci.yml` | CI pipeline for contract tests, reports, and Docker build |
