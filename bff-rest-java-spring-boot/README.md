## Background

In this sample project, we use Specmatic to contract test a Spring Boot BFF in isolation over REST/OpenAPI. Specmatic auto-generates tests from the BFF API spec, starts mocks for the REST Order API and Kafka product audit dependency, and validates that the BFF response and dependency calls match the executable contracts.

* [Product Search BFF OpenAPI spec](https://github.com/specmatic/specmatic-order-contracts/blob/main/io/specmatic/examples/store/openapi/product_search_bff_v6.yaml) is used for running contract tests against the BFF.
* [Order API OpenAPI spec](https://github.com/specmatic/specmatic-order-contracts/blob/main/io/specmatic/examples/store/openapi/api_order_v5.yaml) is used for stubbing the backend REST API.
* [Product audits AsyncAPI spec](https://github.com/specmatic/specmatic-order-contracts/blob/main/io/specmatic/examples/store/asyncapi/kafka.yaml) is used for mocking the Kafka dependency.

## Why Specmatic

* **Auto-generated tests from your API spec** - Specmatic reads the OpenAPI and AsyncAPI specs and generates test cases automatically.
* **Intelligent service virtualisation** - Specmatic creates realistic REST and Kafka mocks from the same contracts, so this BFF can be tested without real downstream services.
* **Backward compatibility detection** - Specmatic can compare spec versions and flag breaking changes before they reach production.
* **Works with your existing OpenAPI spec** - no new DSL is needed for REST contract tests.

## Run Contract Tests

### Prerequisites

Install Java 17 and Maven. Set `SPECMATIC_LICENSE_KEY` for Specmatic Enterprise before running the test command. The sample uses the official Enterprise CLI artifact `io.specmatic.enterprise:executable-all:1.19.1`.

For **Unix based systems** and **Windows PowerShell**:

```shell
./mvnw test
```

For **Windows Command Prompt**:

```shell
mvnw.cmd test
```

First run may take 1-2 minutes as Specmatic clones the configured contract repository. Subsequent runs are fast, cached in `.specmatic/`.

The [specmatic.yaml](specmatic.yaml) file configures the BFF contract, dependency mocks, ports, schema resiliency mode, and report output.

#### View Specmatic Test Reports

After running the contract tests, you can view the HTML report generated by Specmatic in [build/reports/specmatic](build/reports/specmatic/). The same directory also contains the CTRF output for CI tooling.

### Test Modes

This sample ships with `schemaResiliencyTests: all` which runs the full test suite including negative/boundary tests. You can adjust the mode in `specmatic.yaml`:

| Mode | What it does |
|------|-------------|
| `none` | Runs tests from named examples only (fastest) |
| `positiveOnly` | Adds all valid input combinations |
| `all` | Adds negative/boundary tests and expects contract-declared 400 responses |

To change, update `specmatic.yaml`:

```yaml
specmatic:
  settings:
    test:
      schemaResiliencyTests: none
```

## How It Works

BFF Spec -> specmatic.yaml -> Specmatic generates requests to your BFF -> Your BFF calls dependency mocks -> Specmatic validates both sides.

When you run the test command, Maven downloads the Specmatic Enterprise CLI, starts the Spring Boot BFF, and invokes `java -jar target/specmatic/specmatic-enterprise.jar run-suite --config specmatic.yaml`. Specmatic reads `specmatic.yaml`, fetches the contracts, starts REST and Kafka dependency mocks, generates the BFF tests, and validates the responses.

## Configuration

| Environment Variable | Default | Description |
|---------------------|---------|-------------|
| `SUT_PORT` | `8080` | Spring Boot application port |
| `SUT_BASE_URL` | `http://localhost:8080` | Base URL used by Specmatic tests |
| `STUB_BASE_URL` | `http://localhost:8090` | Base URL used by the BFF to call the REST dependency |
| `STUB_HOST` | `localhost` | REST dependency mock host |
| `STUB_PORT` | `8090` | REST dependency mock port |
| `KAFKA_HOST` | `localhost` | Kafka mock host |
| `KAFKA_PORT` | `9092` | Kafka mock port |
| `KAFKA_BROKER` | `localhost:9092` | Kafka bootstrap server used by the BFF and Specmatic |

## Project Structure

| File | Purpose |

| `Dockerfile` | Production container image |
| `.github/workflows/ci.yml` | CI pipeline: test + Docker build |
| `.specmatic-sample-manifest.json` | Generated sample metadata and verification results |
