## Background

This sample demonstrates a Spring Boot BFF contract-tested over REST/OpenAPI. Specmatic reads the BFF API spec and auto-generates requests against this service while also mocking the downstream Order API and Kafka dependency from the same contract repository.

* [Order BFF OpenAPI spec](https://github.com/specmatic/specmatic-order-contracts/blob/main/io/specmatic/examples/store/openapi/product_search_bff_v6.yaml) is used for running contract tests against this BFF.
* [Order API OpenAPI spec](https://github.com/specmatic/specmatic-order-contracts/blob/main/io/specmatic/examples/store/openapi/api_order_v5.yaml) is used for stubbing the REST backend dependency.
* [Kafka AsyncAPI spec](https://github.com/specmatic/specmatic-order-contracts/blob/main/io/specmatic/examples/store/asyncapi/kafka.yaml) is used for the async dependency mock.

## Why Specmatic

* **Auto-generated tests from your API spec** - Specmatic reads OpenAPI and AsyncAPI specs and generates contract test cases automatically.
* **Intelligent service virtualisation** - Specmatic creates realistic REST and Kafka mocks from the same specs, so the BFF can be tested in isolation.
* **Backward compatibility detection** - Specmatic can compare spec versions and flag breaking changes before they reach production.
* **Works with existing OpenAPI specs** - no new DSL is needed for REST contract tests.

1. Spring Boot BFF written in Java 17

3. Maven Wrapper for build and test execution
4. JRE 17+ and `SPECMATIC_LICENSE_KEY` for Enterprise runtime access

## Run Contract Tests

### Prerequisites

* JDK 17+
* Access to `io.specmatic.enterprise:executable-all:1.18.0`
* `SPECMATIC_LICENSE_KEY` exported in your shell or configured in CI secrets

For **Unix based systems** and **Windows PowerShell**:

```shell
./mvnw test
```

For **Windows Command Prompt**:

```shell
mvnw.cmd test
```

First run takes 1-2 minutes as Specmatic clones the contract repository. Subsequent runs are fast, cached in `.specmatic/`.

The [specmatic.yaml](specmatic.yaml) file configures which contracts are tested and which downstream services Specmatic mocks.

#### View Specmatic Test Reports

After running the contract tests, you can view the HTML report generated by Specmatic here:
[build/reports/specmatic/html/index.html](build/reports/specmatic/html/index.html)

### Test Modes

This sample ships with `schemaResiliencyTests: all` which runs the full test suite including negative and boundary tests. You can adjust the mode in `specmatic.yaml`:

| Mode | What it does |
|------|-------------|
| `none` | Runs tests from named examples only |
| `positiveOnly` | Adds all valid input combinations |
| `all` | Adds negative and boundary tests, expecting 400 for invalid inputs |

```yaml
specmatic:
  settings:
    test:
      schemaResiliencyTests: none
```

## How It Works

BFF Spec -> specmatic.yaml -> Specmatic generates requests to the BFF -> the BFF calls the Specmatic REST mock -> Specmatic validates both sides.

When you run the test command, the Maven test starts this Spring Boot app and invokes the Enterprise CLI directly with `java -jar`. Specmatic reads `specmatic.yaml`, fetches the contracts from GitHub, starts dependency mocks, generates contract tests, and validates every response against the executable specs.

## Configuration

| Environment Variable | Default | Description |
|---------------------|---------|-------------|
| `SUT_PORT` | `8080` | Spring Boot application port |
| `SUT_BASE_URL` | `http://localhost:8080` | Base URL used by tests |
| `STUB_BASE_URL` | `http://localhost:8090` | REST backend mock URL |
| `BACKEND_API_KEY` | `sample-api-key` | Outbound `Authenticate` header for the backend mock |
| `BROKER_HOST` | `localhost` | Kafka mock host |
| `BROKER_PORT` | `9092` | Kafka mock port |
| `BROKER_URL` | `localhost:9092` | Kafka mock server address |

## Project Structure

| File | Purpose |
|------|---------|
| `specmatic.yaml` | Contract test configuration |
| `pom.xml` | Maven build and Enterprise CLI artifact resolution |
| `src/main/java/...` | BFF controller, client, models, and error handling |
| `src/test/java/.../ContractTest.java` | Starts the app and runs `java -jar` Specmatic Enterprise CLI |
| `Dockerfile` | Production container image |
| `.github/workflows/ci.yml` | CI pipeline for tests, reports, and Docker build |
