## Background

In this sample project, we use Specmatic to contract test a Spring Boot backend Order API in isolation over REST/OpenAPI. Specmatic reads the executable OpenAPI contract and auto-generates tests for the Products and Orders API, including JSON requests, text/plain success responses, multipart image upload, and contract-shaped error responses. The [Order API OpenAPI spec](https://github.com/specmatic/specmatic-order-contracts/blob/main/io/specmatic/examples/store/openapi/api_order_v5.yaml) is used for running contract tests against this API; the backend keeps Products, Orders, and its Inventory boundary in memory, so no dependency service is stubbed for this backend sample.

## Why Specmatic

* **Auto-generated tests from your API spec** - Specmatic reads the OpenAPI spec and generates contract tests automatically.
* **Works with your existing OpenAPI spec** - no new DSL is needed for REST API contract testing.
* **Backward compatibility detection** - Specmatic can compare spec versions and flag breaking changes before release.
* **Single source of truth** - the same spec drives tests, stubs, and compatibility checks.

## Run Contract Tests

### Prerequisites

Install JDK 17 and Maven 3.9+. Set `SPECMATIC_LICENSE_KEY` to a valid Specmatic Enterprise license key before running the contract tests. This sample uses the official Enterprise runtime artifact `io.specmatic.enterprise:openapi-min:1.18.0`.

First run takes 1-2 minutes as Specmatic clones the contract repository. Subsequent runs are fast because contracts are cached in `.specmatic/`.

The [specmatic.yaml](specmatic.yaml) file configures the contract source, the exact OpenAPI spec path, the system under test base URL, coverage governance, and schema resiliency mode.

### Using the Build Tool

For **Unix based systems** and **Windows PowerShell**:

```shell
./mvnw test
```

For **Windows Command Prompt**:

```shell
mvnw.cmd test
```

#### View Specmatic Test Reports

After running the contract tests, you can view the HTML report generated by Specmatic in the following location:
[build/reports/specmatic/test/html/index.html](build/reports/specmatic/test/html/index.html)

### Test Modes

This sample ships with `schemaResiliencyTests: all` which runs the full test suite including negative/boundary tests. You can adjust the mode in `specmatic.yaml`:

| Mode | What it does |
|------|-------------|
| `none` | Runs tests from named examples only (fastest) |
| `positiveOnly` | Adds all valid input combinations |
| `all` | Adds negative/boundary tests - expects 400 for invalid inputs (default) |

To change, update `specmatic.yaml`:

```yaml
specmatic:
  settings:
    test:
      schemaResiliencyTests: none
```

## How It Works

API Spec (OpenAPI) -> `specmatic.yaml` -> Specmatic generates requests -> Spring Boot responds -> Specmatic validates responses against the spec.

When you run `./mvnw test`, the JUnit contract test starts the Spring Boot app on an available local port, configures Specmatic with that base URL, and invokes the native Specmatic JUnit support. Specmatic reads `specmatic.yaml`, fetches the contract from GitHub, generates test cases from `api_order_v5.yaml`, and validates every response against the OpenAPI contract.

## Configuration

| Environment Variable | Default | Description |
|---------------------|---------|-------------|
| `SUT_PORT` | random available test port, `8080` for normal app startup | Application port |
| `SUT_BASE_URL` | `http://localhost:8080` | Base URL used by Specmatic tests when not overridden by the JUnit adapter |
| `SPECMATIC_LICENSE_KEY` | none | Specmatic Enterprise license key |

## Project Structure

| File | Purpose |
|------|---------|
| `specmatic.yaml` | Contract test configuration pointing to the Order API OpenAPI spec |
| `pom.xml` | Spring Boot, Java, JUnit, and Specmatic Enterprise dependencies |
| `src/main/java/.../api` | Product and Order REST controllers |
| `src/main/java/.../service` | In-memory Products, Orders, and Inventory boundary |
| `src/test/java/.../ContractTest.java` | Native Specmatic JUnit adapter that starts the app and runs contract tests |
| `Dockerfile` | Production container image built from source |
| `.github/workflows/ci.yml` | CI pipeline: test and Docker build |
