## Background

In this sample project, we use Specmatic to contract test a Kotlin Ktor BFF over REST/OpenAPI. Specmatic auto-generates tests from the BFF OpenAPI spec, starts mocks from the dependency contracts, and validates that the BFF forwards requests and responses across the contract boundary correctly.

* [Order BFF OpenAPI spec](https://github.com/specmatic/specmatic-order-contracts/blob/main/io/specmatic/examples/store/openapi/product_search_bff_v6.yaml) is used for running contract tests against the BFF.
* [Order API OpenAPI spec](https://github.com/specmatic/specmatic-order-contracts/blob/main/io/specmatic/examples/store/openapi/api_order_v5.yaml) is used for stubbing the REST backend dependency.
* [Product audits AsyncAPI spec](https://github.com/specmatic/specmatic-order-contracts/blob/main/io/specmatic/examples/store/asyncapi/kafka.yaml) is used for stubbing the Kafka dependency boundary.

## Why Specmatic

* **Auto-generated tests from your API spec** - Specmatic reads OpenAPI and AsyncAPI specs and generates test cases automatically.
* **Intelligent service virtualisation** - dependency mocks come from the same contracts, so the BFF can be tested without real backend services.
* **Backward compatibility detection** - Specmatic can flag breaking API changes before they reach production.
* **Works with your existing OpenAPI spec** - no new DSL is needed for REST contract tests.

## Tech

1. Kotlin 2.4.0 BFF built with Ktor 3.5.0 on Java 17.
2. Specmatic Enterprise Docker image `specmatic/enterprise:1.18.0`.
3. Docker Desktop or a Docker-compatible runtime for contract tests.
4. Maven wrapper for local build and test execution.

## Run Contract Tests

### Prerequisites

* JDK 17+
* Docker
* `SPECMATIC_LICENSE_KEY` for Specmatic Enterprise
* Access to the `specmatic/enterprise:1.18.0` Docker image

For **Unix based systems** and **Windows PowerShell**:

```shell
./mvnw test
```

For **Windows Command Prompt**:

```shell
mvnw.cmd test
```

First run takes 1-2 minutes as Specmatic clones the contract repository. Subsequent runs are fast because contracts are cached in `.specmatic/`.

The [specmatic.yaml](specmatic.yaml) file configures the BFF contract, REST dependency mock, Kafka dependency mock, endpoints, and schema resiliency mode.

### Using Docker

The test command itself runs Specmatic through Docker. To build the application image:

```shell
docker build -t bff-rest-kotlin-ktor .
```

#### View Specmatic Test Reports

After running the contract tests, you can view the HTML report generated by Specmatic here:
[build/reports/specmatic/test/html/index.html](build/reports/specmatic/test/html/index.html)

### Test Modes

This sample ships with `schemaResiliencyTests: all`, which runs the full suite including negative and boundary tests. You can adjust the mode in `specmatic.yaml`:

| Mode | What it does |
|------|-------------|
| `none` | Runs tests from named examples only |
| `positiveOnly` | Adds all valid input combinations |
| `all` | Adds negative and boundary tests, expecting 400 for invalid inputs |

```yaml
specmatic:
  settings:
    test:
      schemaResiliencyTests: none
```

## How It Works

BFF Spec -> specmatic.yaml -> Specmatic generates requests to the Ktor BFF -> the BFF calls the Specmatic REST backend mock -> Specmatic validates both sides.

When you run the test command, JUnit starts the Ktor app and then invokes `specmatic/enterprise:1.18.0` with `docker run`. Specmatic reads `specmatic.yaml`, fetches the contracts, starts dependency mocks, generates BFF requests, and validates the responses.

## Configuration

| Environment Variable | Default | Description |
|---------------------|---------|-------------|
| `SUT_PORT` | `8080` | Ktor application port |
| `SUT_BASE_URL` | `http://localhost:8080` | Base URL used by Specmatic tests |
| `STUB_BASE_URL` | `http://localhost:8090` | Base URL for the Specmatic REST backend mock |
| `BROKER_HOST` | `localhost` | Kafka mock broker bind host |
| `BROKER_PORT` | `9092` | Kafka mock broker port |
| `BROKER_URL` | `localhost:9092` | Kafka server URL used by the AsyncAPI mock |
| `SPECMATIC_DOCKER_IMAGE` | `specmatic/enterprise:1.18.0` | Enterprise runtime image |

## Project Structure

| File | Purpose |

| `src/main/kotlin/io/specmatic/samples/store/Application.kt` | Ktor BFF routes and backend adapter calls |
| `src/test/kotlin/io/specmatic/samples/store/ContractTest.kt` | Starts the app and runs Specmatic Enterprise through Docker |
| `Dockerfile` | Production container image |
| `.github/workflows/ci.yml` | CI pipeline for tests, reports, and Docker build |
