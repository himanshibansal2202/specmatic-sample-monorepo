## Background

This sample demonstrates a Spring Boot BFF contract-tested over REST/OpenAPI. Specmatic reads the BFF OpenAPI specification, auto-generates requests against this service, and starts dependency mocks from the backend REST and Kafka contracts so the BFF can be verified in isolation.

* [Order BFF OpenAPI spec](https://github.com/specmatic/specmatic-order-contracts/blob/main/io/specmatic/examples/store/openapi/product_search_bff_v6.yaml) is used for running contract tests against this BFF.
* [Backend Order API OpenAPI spec](https://github.com/specmatic/specmatic-order-contracts/blob/main/io/specmatic/examples/store/openapi/api_order_v5.yaml) is used for stubbing the backend REST API.
* [Product audit AsyncAPI spec](https://github.com/specmatic/specmatic-order-contracts/blob/main/io/specmatic/examples/store/asyncapi/kafka.yaml) is configured as the async dependency mock for this BFF contract family.

## Why Specmatic

* **Auto-generated tests from your API spec** - Specmatic reads OpenAPI and AsyncAPI contracts and generates test cases automatically.
* **Intelligent service virtualisation** - backend REST and Kafka dependencies are mocked from the same executable contracts.
* **Backward compatibility detection** - contract changes can be checked before they reach production.
* **Works with your existing OpenAPI spec** - no new DSL is required for REST APIs.

1. Spring Boot 4.0.6 BFF service written in Java 17
2. Specmatic Enterprise Docker image for contract tests and dependency mocks
3. Docker Desktop or Docker Engine for `docker-cli` integration
4. Maven Wrapper for local and CI builds

## Run Contract Tests

### Prerequisites

* JDK 17 or newer
* Docker Desktop or Docker Engine
* `SPECMATIC_LICENSE_KEY` exported in your shell or CI secrets for Specmatic Enterprise

For **Unix based systems** and **Windows PowerShell**:

```shell
./mvnw test
```

For **Windows Command Prompt**:

```shell
mvnw.cmd test
```

First run takes 1-2 minutes as Specmatic clones the contract repository. Subsequent runs are fast because the contracts are cached in `.specmatic/`.

The [specmatic.yaml](specmatic.yaml) file controls the system-under-test contract, dependency mocks, runtime endpoints, and test mode.

### Using Docker Directly

The Maven test already runs Specmatic through Docker. To run the application container separately:

```shell
docker build -t specmatic-sample/bff-rest-java-spring-in-memory .
docker run --rm -p 8080:8080 -e STUB_BASE_URL=http://host.docker.internal:8090 specmatic-sample/bff-rest-java-spring-in-memory
```

#### View Specmatic Test Reports

After running the contract tests, view the Specmatic reports at [build/reports/specmatic/html/index.html](build/reports/specmatic/html/index.html) when generated by the runtime.

### Test Modes

This sample ships with `schemaResiliencyTests: all` which runs the full test suite including negative and boundary tests. You can adjust the mode in `specmatic.yaml`:

| Mode | What it does |
|------|-------------|
| `none` | Runs tests from named examples only |
| `positiveOnly` | Adds all valid input combinations |
| `all` | Adds negative and boundary tests that expect contract-defined 4xx responses |

## How It Works

BFF Spec -> `specmatic.yaml` -> Specmatic generates requests to the BFF -> the BFF calls Specmatic dependency mocks -> Specmatic validates responses against the executable contracts.

The BFF has no local database. It maps `POST /products`, `GET /findAvailableProducts`, `POST /orders`, `GET /orders`, and `GET /monitor/{id}` from the BFF contract to backend behavior where applicable, adding dependency-only headers such as `Authenticate` and `Idempotency-Key` for the backend mock contract.

## Configuration

| Environment Variable | Default | Description |
|---------------------|---------|-------------|
| `SUT_PORT` | `8080` | Spring Boot application port |
| `SUT_BASE_URL` | `http://localhost:8080` | Base URL used by Specmatic tests |
| `STUB_BASE_URL` | `http://localhost:8090` | Backend REST mock URL used by the app |
| `STUB_PORT` | `8090` | Published REST dependency mock port in Docker test runs |
| `BROKER_PORT` | `9092` | Published in-memory Kafka broker port |
| `BROKER_URL` | `localhost:9092` | Kafka broker endpoint for Specmatic |
| `BACKEND_API_KEY` | `sample-api-key` | Header value used to satisfy backend API key shape |
| `BACKEND_IDEMPOTENCY_KEY` | `00000000-0000-0000-0000-000000000001` | Header value used for backend create operations |

## Project Structure

| File | Purpose |

| `src/main/java/io/specmatic/sample/bff` | Spring Boot application source |

| `Dockerfile` | Production container image |
| `.github/workflows/ci.yml` | CI pipeline for tests, reports, and Docker build |
