## Background

In this sample project, we use Specmatic to contract test a Go/Gin BFF in isolation. Specmatic auto-generates tests from the BFF OpenAPI spec and starts mocks for the REST Order API and Kafka product audit dependency, so the BFF can be verified without real downstream services.

* [Order BFF OpenAPI spec](https://github.com/specmatic/specmatic-order-contracts/blob/main/io/specmatic/examples/store/openapi/product_search_bff_v6.yaml) is used for running contract tests against the BFF.
* [Order API OpenAPI spec](https://github.com/specmatic/specmatic-order-contracts/blob/main/io/specmatic/examples/store/openapi/api_order_v5.yaml) is used for stubbing the REST backend.
* [Product audits AsyncAPI spec](https://github.com/specmatic/specmatic-order-contracts/blob/main/io/specmatic/examples/store/asyncapi/kafka.yaml) is used for the Kafka mock.

## Why Specmatic

* **Auto-generated tests from your API spec** - Specmatic reads the OpenAPI and AsyncAPI specs and generates test cases automatically.
* **Intelligent service virtualisation** - dependency mocks are generated from the same contracts the real services implement.
* **Backward compatibility detection** - Specmatic can flag breaking API changes before they reach production.
* **Works with your existing OpenAPI spec** - no new DSL is needed for REST contract tests.

## Tech

1. Go 1.26.5 service written with Gin v1.12.0
2. Specmatic Enterprise CLI using `io.specmatic.enterprise:executable-all:1.19.1`
3. Java 17+ for the Specmatic CLI runtime
4. Kafka dependency mocked by Specmatic's in-memory broker

## Run Contract Tests

### Prerequisites

* Go 1.26.5
* Java 17+
* Maven, used by the test script to fetch `io.specmatic.enterprise:executable-all:1.19.1`
* `SPECMATIC_LICENSE_KEY` when your Enterprise runtime requires it

First run may take 1-2 minutes as Specmatic clones the configured contract repository. Subsequent runs are fast, cached in `.specmatic/`.

### Using the build tool

For **Unix based systems**:
```shell
./scripts/test.sh
```

For **Windows PowerShell**:
```shell
.\scripts\test.ps1
```

For **Windows Command Prompt**:
```cmd
scripts\test.cmd
```

The [specmatic.yaml](specmatic.yaml) file configures the BFF contract, dependency contracts, runtime endpoints, reports, and schema resiliency mode.

#### View Specmatic Test Reports

After running the contract tests, you can view the HTML report generated by Specmatic in [build/reports/specmatic](build/reports/specmatic/). The same directory also contains the CTRF output for CI tooling.

### Test Modes

This sample ships with `schemaResiliencyTests: all` which runs the full test suite including negative/boundary tests. You can adjust the mode in `specmatic.yaml`:

| Mode | What it does |
|------|-------------|
| `none` | Runs tests from named examples only (fastest) |
| `positiveOnly` | Adds all valid input combinations |
| `all` | Adds negative/boundary tests - expects 400 for invalid inputs (default) |

To change, update `specmatic.yaml`:
```yaml
specmatic:
  settings:
    test:
      schemaResiliencyTests: none
```

## How It Works

BFF Spec -> specmatic.yaml -> Specmatic generates requests to your BFF -> Your BFF calls dependency mocks -> Specmatic validates both sides.

When you run the test script, it builds and starts the Gin BFF, runs Specmatic Enterprise CLI against `specmatic.yaml`, and tears the app down when the run completes. Specmatic fetches the contracts from GitHub and starts the REST and Kafka dependency mocks from the same configuration.

## Configuration

| Environment Variable | Default | Description |
|---------------------|---------|-------------|
| `SUT_PORT` | `8080` | Application port |
| `SUT_BASE_URL` | `http://localhost:8080` | Base URL for Specmatic tests |
| `STUB_BASE_URL` | `http://localhost:8090` | REST backend mock base URL |
| `KAFKA_HOST` | `localhost` | Kafka mock host |
| `KAFKA_PORT` | `9092` | Kafka mock port |
| `KAFKA_BROKER_URL` | `localhost:9092` | Kafka broker endpoint used by the BFF |
| `BACKEND_API_KEY` | `sample-api-key` | API key sent to the backend mock as `Authenticate` |
| `SPECMATIC_VERSION` | `1.19.1` | Specmatic Enterprise CLI version |

## Project Structure

| File | Purpose |
|------|---------|
| `specmatic.yaml` | Contract test configuration for the BFF and dependency mocks |
| `cmd/server/main.go` | Application entry point |
| `internal/app/` | Gin routes, request validation, and BFF behavior |
| `internal/dependencies/` | REST backend and Kafka dependency clients |
| `scripts/test.sh` | CLI-mode contract test script for Unix/macOS |
| `scripts/test.ps1` / `scripts/test.cmd` | CLI-mode contract test scripts for Windows |
| `Dockerfile` | Production container image |
| `.github/workflows/ci.yml` | CI pipeline: test + Docker build |
